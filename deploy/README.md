# Деплой и обновление по SSH

Инструкция для администратора: машина на **Ubuntu 22.04/24.04 с Docker**
во внутренней сети, всё делается вручную через SSH. Скрипты, на которые она
опирается, лежат в этом каталоге. Подробности и объяснения каждого шага — в
[РАЗВЁРТЫВАНИЕ.md](../РАЗВЁРТЫВАНИЕ.md).

Везде ниже `<адрес>` — адрес машины во внутренней сети, `/opt/CalcKP` — каталог
установки (так его создаёт `bootstrap.sh`).

## Что нужно заранее

- SSH-доступ к машине пользователем с `sudo`.
- **Docker Engine с плагином compose v2.** Проверка:
  ```bash
  docker --version && docker compose version
  ```
  Нет — `curl -fsSL https://get.docker.com | sudo sh` (или установка из
  внутреннего зеркала, если так принято).
- **Выход машины в интернет** — к GitHub (код), Docker Hub (базовые образы) и
  npm (пакеты при сборке). Проверка:
  ```bash
  curl -sI https://github.com | head -1
  curl -sI https://registry.npmjs.org | head -1
  docker pull hello-world
  ```
  Выхода нет — сразу переходите к разделу [«Без выхода в интернет»](#без-выхода-в-интернет).
- Ресурсы: 2 ГБ памяти (или swap — скрипт добавит), 10 ГБ диска.

## 1. Первая установка

**1.1. Войти на машину и забрать скрипт подготовки.**

```bash
ssh <пользователь>@<адрес>
curl -fsSL https://raw.githubusercontent.com/BaukovGK/CalcKP/master/deploy/bootstrap.sh -o bootstrap.sh
less bootstrap.sh            # прочитать: скрипт правит систему
```

Если на машине нет интернета, но есть на вашем компьютере — скопируйте файл
оттуда: `scp deploy/bootstrap.sh <пользователь>@<адрес>:`.

**1.2. Подготовить машину.**

```bash
sudo bash bootstrap.sh --url http://<адрес>
```

Скрипт повторяемый — уже сделанное не переделывает. Он:

- заводит пользователя `deploy` с вашим SSH-доступом и правом запускать Docker;
- открывает в ufw порт SSH (тот, по которому вы зашли, и настроенный в sshd),
  80 и 443. Если файрвол ведёт сеть компании — добавьте `--skip-firewall`;
- добавляет 2 ГБ swap, если его нет;
- клонирует репозиторий в `/opt/CalcKP`;
- создаёт `.env` со сгенерированными паролем базы, JWT-секретом и паролем роли
  приложения без прав суперпользователя. Пароль первого администратора в файл не
  пишется — его один раз сгенерирует сид.

`--url` — адрес, по которому пользователи будут открывать программу; без него
подставится первый адрес сетевого интерфейса. Проверить потом можно в
`/opt/CalcKP/.env`, строка `PUBLIC_URL`.

**1.3. Проверить готовность.**

```bash
sudo -u deploy bash /opt/CalcKP/deploy/preflight.sh
```

Скрипт ничего не меняет: проверяет Docker, `.env`, свободный порт, память,
права каталога дампов. Строки с `✗` — отказы, с ними дальше не идти; с `!` —
предупреждения.

**1.4. Первый запуск.**

```bash
sudo -iu deploy                  # дальше — под пользователем deploy
cd /opt/CalcKP
bash deploy/update.sh
```

Первая сборка идёт 5–10 минут. Скрипт ждёт, пока бэкенд пройдёт проверку
здоровья, и пишет `update: готово, сборка <коммит>`. Не поднялся за 3 минуты —
печатает хвост логов бэкенда (см. «Если что-то пошло не так»).

**1.5. Войти в программу.**

```bash
docker compose logs backend | grep "пароль первого администратора"
```

Откройте `http://<адрес>` с компьютера во внутренней сети, войдите как
`admin@ntt.local` с этим паролем — программа сразу потребует сменить его. Затем в
«Администрировании» заведите остальных пользователей.

**1.6. Убедиться, что развёрнуто то, что нужно.**

```bash
curl -s http://localhost/api/health; echo
git -C /opt/CalcKP rev-parse --short HEAD
```

В ответе `{"status":"ok","version":"…","build":"<коммит>"}` коммит должен
совпасть со вторым выводом.

## 2. Обновление

Обновление — одна команда. С машины:

```bash
ssh deploy@<адрес>
cd /opt/CalcKP
bash deploy/update.sh
```

или сразу со своего компьютера, не открывая сессию:

```bash
ssh deploy@<адрес> 'cd /opt/CalcKP && bash deploy/update.sh'
```

Что происходит:

1. `git fetch` и `git reset --hard origin/master` — установка приводится к
   главной ветке. Правки, сделанные на машине в файлах репозитория, затираются;
   `.env`, дампы и данные базы не затрагиваются.
2. Пересборка образов и перезапуск стека.
3. При старте бэкенд **сам применяет новые миграции базы** — и перед этим
   снимает дамп с меткой `pre-migrate` в `/opt/CalcKP/backups`. Дамп не снялся —
   миграции не применяются и бэкенд не стартует: откатывать было бы нечем.
4. Скрипт ждёт проверки здоровья бэкенда до 3 минут.

Два обновления одновременно не пойдут: второй запуск увидит блокировку и
выйдет.

После обновления проверьте версию так же, как в шаге 1.6.

> **Неудачное обновление останавливает программу.** Если бэкенд не поднялся,
> прежние контейнеры уже заменены — пользователи увидят ошибку, пока вы не
> исправите причину или не откатитесь (раздел 3). Обновляйте, когда программой
> не работают.

## 3. Откат

Сначала узнайте, меняло ли обновление базу:

```bash
cd /opt/CalcKP
ls -t backups | head -3
```

Свежий файл `ntt-<дата>-pre-migrate.dump` со временем обновления — миграции
применялись. Нет такого — база не менялась.

**База не менялась** — достаточно вернуть код:

```bash
git log --oneline -10                    # найти коммит, на котором всё работало
git reset --hard <коммит>
APP_BUILD=$(git rev-parse --short HEAD) docker compose up -d --build --wait
```

**Миграции применялись** — вернуть нужно и базу. Всё, что пользователи ввели
после обновления, при этом **пропадёт**.

```bash
docker compose stop backend                                      # не даст мигрировать снова
docker compose --profile tools run --rm restore --list           # найти pre-migrate дамп
docker compose --profile tools run --rm restore --yes <файл>     # сам снимет страховочный дамп
git reset --hard <коммит>                                        # иначе миграция применится заново
APP_BUILD=$(git rev-parse --short HEAD) docker compose up -d --build --wait
```

## 4. Автоматическое обновление (по желанию)

Если обновлять руками не хочется, машина может сама проверять ветку и
пересобираться, когда в ней появились новые коммиты. Строка в cron пользователя
`deploy` (`crontab -e`):

```cron
*/5 * * * * cd /opt/CalcKP && bash deploy/update.sh --if-changed >> /home/deploy/ntt-update.log 2>&1
```

`--if-changed` ничего не делает, пока новых коммитов нет. Учтите: cron не
знает, прошли ли проверки в GitHub, и выложит содержимое ветки в любом случае.
Выкладка только после зелёных проверок — агентом GitHub на машине, см. раздел
«Машина во внутренней сети: выкладка агентом» в
[РАЗВЁРТЫВАНИЕ.md](../РАЗВЁРТЫВАНИЕ.md).

## Без выхода в интернет

Код и образы собираются на компьютере с интернетом и Docker, а на машину
переносятся файлами. Docker на машине должен быть уже установлен.

**На компьютере с интернетом** — при первой установке и перед каждым обновлением:

```bash
git clone https://github.com/BaukovGK/CalcKP.git && cd CalcKP     # или git pull в имеющемся клоне
git checkout master

git bundle create ../ntt.bundle master
APP_BUILD=$(git rev-parse --short HEAD) docker compose build
docker pull postgres:16
docker save ntt-calculator-backend ntt-calculator-web postgres:16 | gzip > ../ntt-images.tar.gz

scp ../ntt.bundle ../ntt-images.tar.gz <пользователь>@<адрес>:/tmp/
```

Архитектура компьютера и машины разная (например, Mac на Apple Silicon и обычный
сервер x86-64) — соберите образы под машину:
`DOCKER_DEFAULT_PLATFORM=linux/amd64 docker compose build` (для машины на ARM —
`linux/arm64`).

**На машине, первая установка:**

```bash
sudo git clone -b master /tmp/ntt.bundle /opt/CalcKP
sudo bash /opt/CalcKP/deploy/bootstrap.sh --url http://<адрес>    # клон увидит и не тронет
gunzip -c /tmp/ntt-images.tar.gz | sudo docker load

sudo -iu deploy
cd /opt/CalcKP
docker compose up -d --no-build --wait
```

**На машине, обновление:**

```bash
gunzip -c /tmp/ntt-images.tar.gz | docker load
cd /opt/CalcKP
git fetch /tmp/ntt.bundle +master:refs/remotes/origin/master
git reset --hard origin/master
docker compose up -d --no-build --wait
```

`update.sh` здесь не подходит: он сам ходит в GitHub.

**Храните архив образов предыдущей версии** (переименуйте, например, в
`ntt-images-<коммит>.tar.gz`): после `docker load` новых образов прежние теряют
имя, и откатиться без архива будет не на что. Откат — как в разделе 3, только
перед запуском загрузить прежний архив (`gunzip -c … | docker load`), а вместо
`--build` — `--no-build`.

## Если что-то пошло не так

| Что видно | Что делать |
|---|---|
| `update: стек не поднялся за 3 минуты` и хвост логов | Причина — в этом хвосте: упавшая миграция, ошибка в `.env`, нет места. Полный лог: `docker compose logs --tail=300 backend`. Не исправляется быстро — откат (раздел 3) |
| `дамп не снят — миграции НЕ применяются` | Не пишется каталог дампов или кончилось место: `df -h /opt/CalcKP`, `ls -ld backups`. Запуск без дампа — `BACKUP_BEFORE_MIGRATE=try` в `.env`, на свой риск |
| `permission denied … docker.sock` | Пользователь не в группе `docker` или сессия открыта до добавления — выйти и зайти снова |
| Страница открывается, а вход и данные отвечают 502 | nginx помнит прежний адрес бэкенда после перезапуска одного `backend`: `docker compose restart web` |
| С других компьютеров программа не открывается | `PUBLIC_URL` и `HTTP_PORT` в `.env`, порт в файрволе машины и сети; с самой машины: `curl -sI http://localhost` |
| Не знаю, в каком состоянии установка | `bash deploy/preflight.sh` — проверит всё, ничего не меняя; `docker compose ps` — что запущено |
| Ошибка `git fetch`: запрос пароля или 403 | Репозиторий закрыт, а токена нет: `git remote set-url origin https://<токен>@github.com/BaukovGK/CalcKP.git` (токен только на чтение) |
