## 2. Архитектура книги и поток данных

```
Опросный лист (ОЛ_НАСОСНАЯ_СТАНЦИЯ / ОЛ_ЕМКОСТИ / ОЛ_КОЛОДЦА)   ← ручной ввод
        │  (+ встроенный расчёт объёмов Vэф/Vмин и глубины Нподз)
        ▼
Калькулятор (КНС / ЕМК / колодца)  ← построчная спецификация BOM + труд
        │   цены ← НН (прайс)
        │   веса ← «Вес трубы, ПЭ трубы»
        │   нормативы ← «Для расчетов», «Вспомогат. таблицы», «для шапки»
        │   списки/enum ← «Списки»
        ▼
Итоговый блок (себестоимость → наценка 43% → цена продажи)
        ▼
«Заявка» — закупочный документ-view (агрегация непустых строк калькулятора)
```

Параллельный контур: «Гидравл. расчет» (подбор насоса: кривая системы × кривая насоса) → марка/кол-во насосов в ОЛ → раздел 7 калькулятора.

Листы книги: Инструкции, Содержание, Списки, Инструкции1, ОЛ_КОЛОДЦА, Калькулятор колодца, ОЛ_ЕМКОСТИ, Калькулятор ЕМК, для шапки, ОЛ_НАСОСНАЯ_СТАНЦИЯ, Калькулятор КНС, Заявка, Вспомогат. таблицы, Цветовая библиотека, Гидравл. расчет, Для расчетов, Вес трубы/ПЭ трубы, НН, Справка по подбору АШУ Омега.

## 3. Универсальный «движок строки» (общий для всех трёх калькуляторов)

Каждая товарная/рабочая строка имеет одинаковый набор колонок:

| Кол. | Назначение |
|---|---|
| B | № раздела (1, 1.1, 2 …) |
| C | **Категория** (enum из Списки!AG2:AG17 — 16 значений) |
| D | Наименование (часто формула-CONCATENATE из параметров: `"Труба СК/НПС-К "&DN&"-"&PN&"-"&SN`) |
| E | Доп. параметр / подвариант |
| F | Флаг «Закупка»: `да`, если категория ∉ {Собственное производство, Работы, ФОТ} |
| G | Вес, кг/пм |
| H | **Кол-во за 1 ед. — ручной override** |
| I | Кол-во — **расчётная формула** (геометрия/норматив) |
| J | Общее кол-во: `IF(H=""; I; H)` × флаги включения раздела × кол-во корпусов |
| K | ЕИ (м, шт, кг, м², чел. ч) — определяет физический смысл: кг = формовка, чел.ч = труд |
| L | **Цена — ручной override** |
| M | Цена из прайса: `IFERROR(IF(L<>"";""; VLOOKUP(C&D&K; НН!A:J; 10)); "")` |
| N | Сумма: `IF(L=""; M*J; J*L)` |
| O | Примечание |
| P, Q | МТО / Логистика (заголовки есть, в расчётах не используются) |

**Три ключевых паттерна:**

1. **Двухканальный override.** Количество: расчёт в I, ручной ввод в H перекрывает. Цена: прайс в M, ручной ввод в L перекрывает (для трубы/муфты цена почти всегда вводится вручную — уникальна под проект).
2. **Составной ключ прайса** = `Категория & Наименование & ЕИ` (конкатенация без разделителя) → колонка A листа НН; цена — колонка J (10-я).
3. **ФОТ-строки парами.** К каждой производственной операции добавляется строка ФОТ; трудоёмкость = масса операции (кг) × коэффициент: **0,28 чел.ч/кг** — механическая формовка (`*мех*` в наименовании), **0,56** — ламинирование (`*ламин*`), **1,0** — ручная формовка и отдельные виды ламинирования. `J = ROUNDUP(масса×коэф; 1)`; цена чел.ч = ставка ФОТ из НН.

Разделы включаются/выключаются флагами «Да/Нет» (ячейка C у заголовка раздела или поле ОЛ) — при «нет» J-количества обнуляются.

## 4. Калькулятор КНС (452 строки в эталоне)

> 452 — это непустые строки ЛИСТА: заголовки разделов, подписи компонентов,
> разделители и позиции вместе. Позиций расчёта (строк с категорией) — **288**,
> и лист держит рядом варианты для всех диаметров сразу, из которых заказ
> использует один. Знаменателем полноты материализации 452 быть не может —
> разбор и правильные числа в `Шаблон_КНС_разбор.md`.

### 4.1 Шапка (строки 1–8)
Собирается из ОЛ: G5=DN (E20), I5=подземная часть L (E24/F24), H5=полный габарит=I5+возвышение (E25), G8=PN (E21), I8=SN (E22), J5/K5=DN и кол-во входных патрубков, L5/M5=DN и кол-во напорных. Расчёт гильз: `K8/M8 = IF(DN ≥ 200; CEILING(DN+100; 100); CEILING(DN+100; 50))`, причём при DN < 100 надбавка +100 не применяется (`ntt-calculator/src/engines/survey-kns.ts:233`). F7 — автоподбор PN трубы корпуса по таблице весов. J13 — кол-во корпусов (тираж; итоги домножаются).

### 4.3 Примеры расчётных формул количеств
- Труба корпуса: `I14 = L/1000` м; вес `= I14 × INDEX(ВесТрубы; MATCH("DN;PN;SN"); 3)`
- Придание товарного вида: `I15 = DN/1300 × J14` чел.ч
- Масса формованного дна: `I22 = π·((DN+300)/2000)²·0,01·1850 + ((DN/1000)²·π·0,008·1850)/4` (плотность ламината 1850 кг/м³)
- Ламинирование детали к корпусу: `масса_детали × 3/10` кг ламината
- Верхнее перекрытие: `π·((DN+300)/2000)²·0,006·1850 − масса_горловины×кол-во_люков`
- Теплоизоляция: вертикаль `π·(DN/1000)·(глубина_ТИ/1000)` м²; крышка `π·(DN/2000)²`; защитный слой `S·0,005·1850` кг
- Прорезка отверстия: `Ø·π/1000 × 0,5 × кол-во` чел.ч (0,5 чел.ч на 1 м окружности)
- Подготовка трубы: `(DN/(200·6))·L` чел.ч
- Направляющие насосов: `L×(раб+рез)×2`
- Анкеры: `(глубина·1000·9,8·π·Дн²/4)/27500` (27 500 Н на 1 анкер М16)

### 4.4 Условная логика (флаги)
Дробилка↔корзина (ОЛ!E46, взаимоисключающие), теплоизоляция (E72+глубина E73), фальшпол (C50), задвижка на подводящем (E47), аварийный трубопровод (I47), лестница и её материал (C119/C121), тип крышки СК/металл (E139), МВК-комплект — поручень, откидные люки, перехватывающее устройство, нерж. вентиляция (E27), датчики/расходомер/ШУ (I64–I66), насосы (E55+E56+E57), петли простые/усиленные (DN<2000).

## 5. Калькулятор ЕМК — отличия от КНС

- Длина трубы — из объёма: `CEILING(4V/(π·(D/1000)²)·1000; 100)`, мм вверх до 100 (`ntt-calculator/src/engines/survey-emk-kol.ts:41`).
- Лист **«для шапки»** — таблица габаритов по составному ключу `Расположение&Установка&Наличие шахты`: `B2:B9` — ровно 8 комбинаций (`ВертикальноеПодземнаяДа` … `ГоризонтальноеНаземнаяНет`; варианта «в помещении» из `Списки!AM4` в ключах нет). По этому ключу шапка «Калькулятора ЕМК» тянет габаритную длину, длину трубы, возвышение и объём: `H5/I5/J5/K5 = INDEX('для шапки'!$C$2:$K$11; MATCH(ОЛ_ЕМКОСТИ!$E$24&$E$25&$E$39; 'для шапки'!$B$2:$B$11;); MATCH(H3; 'для шапки'!$C$1:$K$1;))`, и туда же смотрят три `VLOOKUP` самого ОЛ (`F19`, `F28`, `F29`). Но ячейки таблицы — **не константы справочника, а формулы от текущего ОЛ**: длина считается тем же `CEILING(...)` (`D2`, `F6`), возвышение и шахта — прямые ссылки `H2 = ОЛ_ЕМКОСТИ!E26` (300), `J2 = E40` (1200), `K2 = E41+H2` (2300), литеральные нули стоят только в наземных строках и строках «без шахты». Поэтому в приложении лист таблицей не переносится: длина считается формулой, возвышение и шахта — отдельными функциями, возвращающими 300/0 и Ø 1200 при h 2300 (подземная) / 2000 (`survey-emk-kol.ts:60,66`).
- Материал по среде: `D8 = IF(тип="Химстойкая"; "СК/ВЭС"; "СК/НПС")`.
- **Днище — переключатель «Новый/Старый способ»**: горизонтальная ёмкость → эллиптические днища (объём `L5 = π·(DN/1000)³/15`; габаритная длина = длина трубы + DN/2 — `'для шапки'!C8 = F8 + 'Калькулятор ЕМК'!G5/2`, что при DN 3000 даёт ровно +1,5 м; в приложении надбавка зашита константой 1500 мм `ELLIPTIC_EXTRA_MM` — `survey-emk-kol.ts:57`, т.е. верна только для DN 3000; массы из матрицы «Для расчетов»); вертикальная → плоское/формованное. В приложении переключатель стал тумблером ОЛ «эллиптические / цилиндрические» (цилиндрические = «Новый способ»: +1,5 м трубы, ламинация косых и центрального стыков); масса эллиптических — из матрицы по DN и строке длины, крепление к трубе — 2 × Мс (Вопросы_заводу §6е).
- Есть разделы «Напорный трубопровод» и «Насосное оборудование» (когда ёмкость с насосами), гидравлический блок — приток, напор, кол-во рабочих/резервных, марка — прямо в ОЛ_ЕМКОСТИ.
- ОЛ ёмкости: объём, DN, PN, SN, расположение (гориз./верт.), установка (наземная/подземная/в помещении), шахта обслуживания (d, h), патрубки, насосы, дробилка/корзина, ШУ+датчики, вентиляция, теплоизоляция.

## 7. Гидравлический расчёт (лист «Гидравл. расчет»)

Полуручной лист. Входы: расход на 1 нитку `Q = приток/(3,6·кол-во ниток)`, отметки (планировка, ввод, вывод, мин. уровень воды, диктующая точка), внутренние диаметры и длины напорного трубопровода в КНС и вне.

- Скорость: `V = 4Q/(π·d²)`
- Геометрический напор: `Hгеом = отметка_дикт − мин_уровень + высота_рамы`
- Потери: по длине `1000i·к·L` + местные; свободный напор на излив 1 м
- **Требуемый напор:** `Hтр = Hгеом + ΣHпот + Hизл`
- Сопротивление системы `S = (Hтр − Hгеом)/Q²`; кривая системы `H = Hгеом + S·Q²`
- Кривая насоса — паспортные точки Q–H вручную; пересечение = рабочая точка → марка насоса в ОЛ.

Ячейка A22 — свободный текстовый расчёт потерь под конкретный проект (разный во всех файлах).

**Что есть в приложении вместо этого.** Подбор идёт ПО ПАСПОРТНОЙ КРИВОЙ. `POST /api/pump-station/select-pump` берёт каталог `Pump` (61 модель Vandjord VSL) вместе с точками характеристики `PumpCurvePoint` (`backend/prisma/seed-data/pump-curves.json` — 56 моделей, 559 точек из выгрузки VJ Select) и для расхода на один насос `Q/n_раб` интерполирует кривую (`backend/src/utils/pump-curve.ts`): насос годится, если в этой точке он даёт напор не меньше требуемого. Напор при параллельной работе не делится. Требуемый запас по напору — окно **0,5…2,0 м** (требование завода): нижняя граница жёсткая, верхняя — предпочтение. Запас страхует не рост притока (он уже заложен в требуемый напор), а то, что реальный насос может не выдать паспортные значения — износ колеса, допуски изготовления, отличие условий от стендовых. Из подходящих берётся наименьший достаточный: сначала попавшие в окно, внутри группы — с минимальной мощностью на валу (`backend/src/utils/pump-selection.ts`). Остальные возвращаются в `candidates` для выбора вручную, а модели, дотянувшие до напора без нужного запаса, — отдельным списком `belowMargin`. У пяти моделей DN50/DN65 кривых нет (вторичные источники) — для них осталась грубая проверка по диапазонам с пометкой `APPROXIMATE_MATCH`. Диаметр напорного трубопровода в листе — вход, проверяется только скорость; обратной задачи там нет, `D = √(4Q/(π·V))` с округлением вверх до типоразмера ПЭ-трубы (V = 1,5 м/с по умолчанию) добавлена нами — `backend/src/utils/pipe-hydraulics.ts:68`. **В рабочем сценарии оба подбора вызываются из опросного листа КНС** (`ntt-calculator/src/composables/usePumpSelection.ts`): марка насоса уходит в расчёт, диаметр напорного показывается подсказкой. Не заменена только графическая часть листа — кривые Q–H и рабочая точка на их пересечении (ТЗ §9.7).

> **Что исправил переход на кривые.** Прежняя прямоугольная рамка `Qmin…Qmax × 0…Hmax` врала в обе стороны, и её ошибки видны на реальных листах.
>
> На ОЛ3487 (45,23 м³/ч на насос, напор 12,9 м) рамка выбирала `VSL.80.37.4.5.0D`, у которого кривая в этой точке даёт **12,69 м — меньше требуемого**: `Hmax` 17 м достигается только при Q ≈ 0. Кривая его отбрасывает и допускает `VSL.100.55.4.5.0D` (16,89 м) — тот, что стоит в проекте.
>
> Вторая ошибка была в самом каталоге: `capacityMinM3h` содержал НОМИНАЛЬНЫЙ расход вместо нижней границы рабочего окна, из-за чего отсев выбрасывал модели, которые производитель для такой точки допускает. Окна приведены к `min_q…max_q` выгрузки — изменились у всех 56 моделей с кривыми.
>
> Контроль на проектных томах: ДУДС24и/ДУДС31и (318,84 м³/ч; 13,29 м) → `VSL.200.190.4.5.1D`, рабочая точка сходится с проектом до сотых. Рабочая точка ниже номинала (41,65 м³/ч; 12,96 м), на которой рамка отвечала отказом, теперь подбирается.
>
> **Окно запаса 0,5…2,0 м спорит с двумя проектами — и в обоих случаях по делу.** На ОЛ3487 в окно попадает единственная модель `VSL.150.75` (0,63 м, 4,04 кВт); проектный `VSL.100.55` избыточен по запасу (3,99 м) и остаётся в списке выбора, а `VSL.100.37` (0,34 м) отсекается по минимуму. На ДУДС24и проектный `VSL.200.190` даёт запас ровно **0,00 м** — рабочая точка лежит на кривой, то есть именно тот случай, который правило и запрещает; он уходит в `belowMargin` и доступен только осознанным выбором.
>
> Диаметр напорного алгоритм даёт Ø110 мм при DN 150 в листе: проект берёт трубу крупнее расчётной (запас и унификация с патрубком КНС), это инженерный выбор поверх гидравлики.

В ОЛ_НАСОСНАЯ_СТАНЦИЯ встроен расчёт объёмов: `Vэф = Q/(4·пусков_в_час·n_раб)`, `Vмин = (Q/n)·t/60`, `hраб = 4·Vмин/(π·DN²)`, `hР = hраб + 0,3 + h_рамы + h_мин_насоса`, `Нподз = ROUNDUP((глубина_лотка + hР)·1000; −2)` → автоматически определяет глубину подземной части корпуса (ячейки N40, N41, N44, N45, N46/P46). Число пусков в час выложено в строке 40 тремя вариантами — `P40` = 5, `Q40` = 10, `R40` = 20 при подписи `S40` «пусков в час», — и формула шаблона ссылается на `P40` = 5; в приложении зашито 10 (`STARTS_PER_HOUR`, `ntt-calculator/src/engines/survey-kns.ts:15`), что сходится с эталоном ОЛ3487 (контроль ниже даёт Vэф 1,13 только при 10). `t` = 5 мин — `P41` (подпись `S41` «поминутная работа»). В `Vмин` шаблон делит приток на литеральную `2` (`N41 = (E51/2)·P41/60`), приложение — на число рабочих насосов `n` (`survey-kns.ts:115`); в эталоне n = 2, поэтому контроль совпадает. **Vраб самостоятельной величиной не является** — в листе это ссылка `Vраб = Vмин` (N42 = N41), поэтому рабочая высота считается от Vмин (`ntt-calculator/src/engines/survey-kns.ts:116`, `backend/src/utils/pump-station-dimensions.ts:218`). Контроль (ОЛ3487): Q 25,13 л/с · DN 3000 · n 2 · лоток 9910 мм → Vэф 1,13 · Vмин 3,77 · hраб 0,533 · hР 1,620 · **Нподз 11 600 мм**.

## 8. Экономика (итоговый блок — одинаков во всех файлах)

1. Σ чел.ч участка фитингов и участка РМУ (разделение по `"*изготов*"` в наименовании работ)
2. **ФОТ на ПЗР:** `часы_фитингов/11`, ROUNDUP до 0,1 × ставка ФОТ
3. **Ацетон:** `5% от массы формовки (кг)` × 109,4 ₽ (старое поколение: 126,5)
4. **СИЗ и РМ:** `ROUNDUP(часы_фитингов + 302)` × 122 ₽ (стар.: 120) — ПЗР в этой формуле не участвует; 302 — константа шаблона (`J446 = ROUNDUP(J441 + 302;)`), физический смысл требует уточнения у завода (`ntt-calculator/src/engines/economics.ts:50,216`)
5. **Накладные расходы:** `ROUNDUP(часы_фитингов + ПЗР; 0,1)` × **1584,73 ₽/чел.ч** (стар.: 1089,56)
6. **ИТОГО себестоимость с НДС** = Труба/муфта + Формовка + Работы ФОТ + Материалы на закупку + Прочие (3+4+5). ПЗР (п. 2) попадает в корзину «Работы, ФОТ», а не в «Прочие». НДС «зашит» в цены НН, отдельной строкой не выделяется.
7. **Наценка = 0,43** (константа во всех 6 файлах)
8. **Цена продажи** = `ROUNDUP(себестоимость × 1,43; −2)` (до 100 ₽)
9. **Рентабельность** = (Цена − Себест.)/Цена ≈ **30,07%**

Тираж: при кол-ве корпусов ≥ 2 итоги домножаются (колонки «за 1 корп. / за N корп.»).

## 10. Сравнение 6 файлов — выводы

**Стабильно (зашивается в приложение как шаблон):**
- каркас 7 разделов калькулятора КНС и аналогичные каркасы ЕМК/колодца, порядок и подписи;
- все системные формулы: геометрия количеств, ФОТ-коэффициенты 0,28/0,56/1,0, ключ прайса, SUMIF-итоги;
- экономика: ПЗР=часы/11, ацетон 5%, накладные=часы×ставка, наценка 0,43, округление до 100 ₽;
- структура ОЛ (наборы полей) и справочник «Списки».

**Меняется от расчёта к расчёту (должно быть редактируемым):**
- все входы ОЛ (тип НС, DN, глубины, SN, патрубки, расход, напор, марка/кол-во насосов, флаги);
- число строк внутри разделов (прежде всего «Напорный трубопровод» и «Оборудование») — динамические таблицы;
- ручные overrides количеств (H) и цен (L), включая ручные арифметические выражения (`=1.55*2+2.88*2+…`);
- свободный текст гидравлического расчёта и точки кривой насоса;
- версия прайса НН (ставка ФОТ, накладных, цены) — критично версионирование.

**Расхождения с ТЗ v1.0** (учтены в ТЗ начиная с v1.1: пп. 1–3 и бо́льшая часть п. 5 — в §9 «Модель расчёта изделия», п. 4 — в §5.6 «Опросный лист»; каталог АШУ из п. 5 в §9 не описан и числится в §7 «Нереализованные модули»):
1. ТЗ описывает калькулятор как свободное дерево «связки→группы→подгруппы→строки». Реальный процесс — **шаблонная спецификация** с предрассчитанными количествами из ОЛ и точечными overrides. Решено в пользу шаблона: ветка свободного дерева удалена коммитом a1e3cc9 (`stores/calculator.ts`, `engines/cost.ts`, `types/calculator.ts`, `CalcBundle/CalcGroup/CalcSubgroup/CalcRow.vue`, `CalculatorView.vue`, маршрут `/calculator-legacy`), а ТЗ §9.1 закрепило формулировку «реальный расчёт — не свободное дерево, а шаблонная спецификация изделия».
2. `PriceItem.lookupKey = "category:name"` неверен — реальный ключ **(категория, наименование, ЕИ)**.
3. Типы строк ТЗ (МАТ/РАБ/ФОТ/ЗАК) не совпадают с реальными категориями (16 шт.); ФОТ-автопересчёт должен идти от **массы (кг)** родительской строки с коэффициентами 0,28/0,56/1,0, а не только от количества РАБ.
4. Поля опросных листов в ТЗ (§5.6) — малая часть реальных; нужно расширение (см. дополнение ТЗ).
5. Отсутствуют в ТЗ: справочники весов труб и инженерных матриц, каталог АШУ, гидравлический расчёт, итоговый экономический блок, «Заявка на закупку», тираж корпусов, атрибут «вид НС» (КНС/ЛНС/ДНС — конструктивно одно изделие, разница только в среде стока).
