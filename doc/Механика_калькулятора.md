# Диздок: механика Калькулятора

**Документ:** техническое описание игровой механики расчёта стоимости изделия
**Связанные документы:** `ТЗ.md` (§5.5, §9), `Реверс_калькуляторов.md` (формулы и первоисточник)
**Версия:** 1.0 · 2026-07-13

---

## 1. Концепция

Инженер отвечает на вопросы опросного листа — система сама собирает полную спецификацию изделия с ценами и трудозатратами. Дальше инженер не «считает смету», а **тюнингует заготовку**: включает/выключает блоки, правит отдельные количества и цены. Система мгновенно пересчитывает итог и показывает цену продажи.

Ключевое ощущение: *«я управляю изделием, а не таблицей»*. Excel-предок требовал знать, какие ячейки трогать можно, а какие нельзя; здесь запрещённых ячеек нет — есть параметры, расчётные значения и явные ручки-переопределения.

**Антицель:** свободный табличный редактор, где каждый расчёт строится с нуля. Проверено реверсом: 6 реальных смет = один каркас + точечные правки.

## 2. Роли

| Роль | Что делает в механике | Мотивация |
|---|---|---|
| ENGINEER | Заполняет ОЛ, тюнингует расчёт, двигает в CALC | Быстро получить корректную смету |
| MANAGER | Проверяет, возвращает, утверждает | Уверенность, что маржа не потеряна |
| BUYER/ADMIN | Ведёт прайс НН | Актуальные цены = честный итог |
| Система | Считает всё, что можно посчитать | — |

## 3. Core loop

```
 ┌─────────────────────────────────────────────────────────┐
 │ 1. ОПРОСНЫЙ ЛИСТ                                        │
 │    выбрал тип изделия → заполнил параметры и флаги      │
 └────────────────┬────────────────────────────────────────┘
                  ▼  «Создать расчёт» (материализация шаблона)
 ┌─────────────────────────────────────────────────────────┐
 │ 2. РАСЧЁТ (заготовка)                                   │
 │    разделы созданы, количества посчитаны, цены          │
 │    подтянуты, ФОТ-спутники добавлены                    │
 └────────────────┬────────────────────────────────────────┘
                  ▼  цикл тюнинга (основной геймплей)
 ┌─────────────────────────────────────────────────────────┐
 │ 3. ТЮНИНГ                                               │
 │    вкл/выкл раздел · добавить/удалить строку ·          │
 │    override количества · override цены ·                │
 │    закрыть «красные» строки (нет цены)                  │
 │        └── каждое действие → мгновенный пересчёт итога  │
 └────────────────┬────────────────────────────────────────┘
                  ▼
 ┌─────────────────────────────────────────────────────────┐
 │ 4. ИТОГ: себестоимость → наценка → цена продажи         │
 │    → статусы CALC → REVIEW → APPROVED → выгрузки        │
 │      (КП, Заявка на закупку, снапшот, Битрикс24)        │
 └─────────────────────────────────────────────────────────┘
```

Петля второго порядка: изменение параметра ОЛ *после* создания расчёта → система предлагает пересчитать затронутые расчётные количества (ручные overrides не трогаются, см. §8.3).

| Сущность | Суть | Аналог в Excel |
|---|---|---|
| **Изделие (deviceType)** | KNS (= КНС/ЛНС/ДНС, конструктивно одно изделие, вид НС — атрибут), EMK, KOL | Три листа-калькулятора |

| **Раздел** | Сборка верхнего уровня шаблона: блок спецификации с флагом включения и подытогами | «1. Корпус», «5. Напорный трубопровод»… |
| **Строка** | Атом расчёта: материал / работа / ФОТ | Строка листа |

| **Справочники** | Веса труб (DN;PN;SN), инженерные матрицы, BOM-комплекты узлов, каталог АШУ | Вес трубы, Для расчетов, Вспомогат. таблицы, Справка АШУ |
| **Снапшот** | Замороженная копия расчёта + версия прайса | Файл «АКТ» |

## 5. Механика строки (атом системы)

Каждая строка — конечный автомат с двумя независимыми каналами: **количество** и **цена**.

### 5.1 Канал количества

```
qtyCalc  ──(формула шаблона от ОЛ и справочников)──►  read-only, серый
qtyManual ──(ввод инженера)────────────────────────►  приоритет, синий
qty = qtyManual ?? qtyCalc
     × флаг раздела (выкл → 0)
     × кол-во корпусов (тираж)
```

Правила:
- `qtyCalc` никогда не редактируется и никогда не теряется: сброс override возвращает расчётное значение (кнопка «↺ к расчётному»).
- Ввод `qtyManual` разрешает произвольные арифметические выражения (`1.55*2+2.88*2`) — в Excel так считают длины; выражение сохраняется, отображается результат.
- Строка без формулы (добавленная вручную) имеет только `qtyManual`.

### 5.2 Канал цены

```
priceCatalog ──(поиск в прайсе по ключу C+N+U)──►  read-only, серый
priceManual  ──(ввод инженера)──────────────────►  приоритет, синий
price = priceManual ?? priceCatalog
sum   = qty × price
```

Правила:
- Промах по прайсу (`priceCatalog = null`) и нет `priceManual` → строка **красная**, сумма = 0, счётчик «незакрытых» строк в шапке. Типовой случай — труба/муфта корпуса: цена всегда договорная, вводится вручную.
- Смена версии прайса → `priceCatalog` пересчитывается, `priceManual` не трогается, но подсвечивается дельта (было/стало у каталожной цены).

### 5.3 Классификация

- `category` — из фиксированного списка 16 категорий. Категория определяет флаг «Закупка»: категории «Собственное производство», «Работы», «ФОТ» — не закупка, остальные 13 — закупка (попадают в Заявку).
- `unit` определяет физический смысл: `кг` — формовка/ламинат (масса участвует в расчёте ФОТ и ацетона), `чел. ч` — труд (участвует в накладных), прочие — штучные материалы.
- Наименования собственного производства генерируются: `Труба СК/НПС-К {DN}-{PN}-{SN}`, `Стеклокомпозитная гильза Ø{D}` — при смене параметров ОЛ наименование и ключ прайса перегенерируются.

## 6. Механика ФОТ-спутников

К каждой производственной операции (строка «Собственное производство» с ЕИ=кг) система автоматически прикрепляет строку-спутник «ФОТ»:

```
трудоёмкость (чел.ч) = ROUNDUP( масса_операции_кг × k , 0.1 )

k = 0.28  если наименование операции содержит «мех»    (механическая формовка)
k = 0.56  если содержит «ламин»                        (ламинирование)
k = 1.0   иначе                                        (ручная формовка и особые случаи)
```

- Спутник реагирует на итоговое `qty` родителя (после override), не на `qtyCalc`.
- Цена спутника = позиция прайса «ФОТ / ФОТ / чел. ч» (актуальная ставка 1207,8 ₽).
- Спутник можно переопределить вручную (H-канал), но нельзя удалить отдельно от родителя.
- Отдельные строки узлов каталога задают коэффициент явно (особые ламинирования с k=1.0) — коэффициент хранится в строке узла, эвристика по подстроке — значение по умолчанию.

## 7. Механика разделов

### 7.1 Каркас KNS (эталон, порядок фиксирован)

1. Корпус (труба, днище, патрубки, гильзы, фальшпол, теплоизоляция, петли, дробилка/корзина, работы)
2. Лестница
3. Перекрытие, площадка и несущие балки
4. Вентиляционный стояк
5. Напорный трубопровод ← самый «живой»: длина сильно меняется от заказа к заказу
6. Крепёж
7. Оборудование и запорная арматура

EMK: + автогабариты из объёма, эллиптические днища (гориз.), шахта обслуживания. KOL: без насосов и напорного трубопровода, + горловина.

### 7.2 Триггеры включения (флаг ← поле ОЛ)

| Блок | Триггер | Поведение |
|---|---|---|
| Дробилка ↔ Корзина | ОЛ «дробилка/корзина» | Взаимоисключающие: включение одного обнуляет другой |
| Теплоизоляция | ОЛ «теплоизоляция» + глубина | Выкл → qty всех строк блока = 0 |
| Фальшпол | флаг раздела | Меняет и конструкцию днища («формованное дно» ↔ «плоское днище») |
| Задвижка на подводящем | ОЛ «арматура на подводящем» | Вкл → фланцевый патрубок |
| Лестница: нерж ↔ алюминиевая | выбор в разделе | Переключает наборы строк |
| Крышка: стеклокомпозит ↔ металл | выбор в разделе | Обнуляет формовку горловины при металле |
| МВК-комплект | ОЛ «По ТТ МВК» | Один флаг включает сразу: поручень, откидные люки, перехватывающее устройство, нерж. вентиляцию |
| Датчики / расходомер / ШУ | ОЛ, по-элементно | Строки раздела 7 |
| Горловина (KOL) | ОЛ «горловина» + d,h | Блок горловины |
| Насосы | ОЛ кол-во раб+рез+запас | Кол-во насосов, АТМ, поплавков (=раб+рез+2), направляющих |

Выключенный раздел не удаляется: строки остаются видимыми в свёрнутом «призрачном» состоянии (qty=0, в итог не входит) — включение обратно восстанавливает всё, включая overrides.

## 8. Механика пересчёта (reactivity)

### 8.1 Граф зависимостей

```
ОЛ-параметр ──► qtyCalc строк ──► qty ──► масса/часы ──► ФОТ-спутники
                                   │                        │
Прайс ──► priceCatalog ──► price ──┴──► sum ──► подытоги раздела
                                                  │
                                     итоговый блок (§9) ──► цена продажи
```

Любое изменение распространяется вниз синхронно, за один тик; итог всегда консистентен.

### 8.2 Что на что влияет (примеры)

- DN корпуса → вес трубы (справочник DN;PN;SN), масса днища, перекрытия, теплоизоляции, наименования труб/гильз, тип петель (DN<2000 — простые), чел.ч «товарного вида» (DN/1300).
- Глубина L → длина трубы, теплоизоляция, лестница, направляющие, анкеры.
- DN патрубка → диаметр гильзы `CEILING(DN+100; 50|100)`, нормы формовки патрубка (справочник), прорезка отверстия (0,5 чел.ч/м окружности).
- Расход/напор → гидравлика → рекомендация насоса → раздел 7.

### 8.3 Конфликт «ОЛ изменился после тюнинга»

Правило: **расчётные значения обновляются всегда, ручные — никогда молча**. Строки, где `qtyManual`/`priceManual` перекрывает изменившееся расчётное значение, помечаются значком конфликта; инженер решает по каждой: оставить override или сбросить к новому расчётному. Массовое действие «сбросить все конфликты» доступно.

## 9. Механика итогов (экономика)

Пайплайн поверх суммы строк, единый для всех изделий:

```
часы_фитингов = Σ чел.ч работ без «изготов» в наименовании
часы_РМУ      = Σ чел.ч работ с «изготов»
масса_формовки = Σ qty строк с ЕИ=кг

ПЗР        = ROUNDUP(часы_фитингов / 11, 0.1) × ставка_ФОТ
Ацетон     = ROUNDUP(масса_формовки × 0.05, 0.1) × цена_ацетона
СИЗ и РМ   = ROUNDUP(часы_фитингов + 302) × цена_СИЗ       ← ЕИ «ед.», НЕ ПЗР (см. ниже)
Накладные  = ROUNDUP(часы_фитингов + ПЗР, 0.1) × ставка_накладных   ← 1584.73 ₽/чел.ч

Себестоимость (с НДС) = Материалы_закупка + Труба_муфта + Формовка
                      + Работы_ФОТ(вкл. ПЗР) + Прочие(Ацетон+СИЗ+Накладные)

Цена продажи   = ROUNDUP( Себестоимость × (1 + наценка), до 100 ₽ )   ← наценка 0.43
Рентабельность = (Цена − Себестоимость) / Цена                        ← справочно ≈ 30%
```

> **Уточнение по первоисточнику (2026-07-16).** Формулы сверены с `Шаблон 3.0.xlsx`, лист «Калькулятор КНС»:
> - ПЗР `J443 = ROUNDUP(часы/11; 0,1)` ✓, ацетон `J445 = ROUNDUP(масса×0,05; 0,1)` ✓, накладные `J447 = ROUNDUP(J441+J443; 0,1)` ✓ — совпадают.
> - **СИЗ `J446 = ROUNDUP(J441+302,)` — расходится с прежней редакцией.** ПЗР в формуле не участвует; `302` — константа шаблона, ЕИ «ед.». Реализуется как в эталоне; **❓ смысл константы 302 требует уточнения у завода**.
> - **ПЗР входит в корзину «Работы, ФОТ»** (`N453 = N441+N443+N442`), а **не** в «Прочие» (`N455 = ацетон+СИЗ+накладные`).
> - Себестоимость `N449 = N454+N451+N452+N455+N453` — ровно 5 корзин.

- Наценка — редактируемое поле расчёта (по умолчанию из настроек), MANAGER видит рентабельность в реальном времени.
- Ставки (ФОТ, накладные, ацетон, СИЗ) — позиции прайса, а не константы кода: обновление прайса меняет экономику всех новых расчётов.
- НДС отдельно не выделяется — цены прайса с НДС (правило предметной области).

### 9.1 Тираж

Поле «Кол-во корпусов» (≥1). При N≥2 итоговый блок показывает две колонки: «за 1 корп.» / «за N корп.»; все составляющие домножаются на N.

## 10. Прогрессия статусов

```
DRAFT ──ENGINEER──► CALC ──MANAGER──► REVIEW ──MANAGER──► APPROVED
                      ▲                  │
                      └────«вернуть»─────┘         ADMIN: любой → REJECTED
```

- APPROVED замораживает расчёт: создаётся снапшот (строки + версия прайса + итоги), редактирование блокируется, цена уходит в сделку Битрикс24.
- Красные строки (нет цены) блокируют переход CALC → REVIEW.

## 12. Инварианты и антиправила

1. Сумма итогового блока всегда равна сумме включённых строк + начисления §9 (в Excel это контролировалось дублирующей формулой — здесь инвариант движка, покрывается тестами).
2. Ручной ввод никогда не перезаписывается системой без подтверждения.
3. Формулы живут в реестре функций (код), состав узлов — в каталоге (конфигурация). Вставка узла в расчёт — **материализация**: копия состава с зафиксированными расчётными значениями, применёнными ценами, ставками и коэффициентами. Расчёт самодостаточен; изменения каталога и прайса влияют только на новые вставки. Снапшот при APPROVED замораживает документ целиком.
4. Ключ прайса — тройка (категория, наименование, ЕИ); символ `~` в наименованиях запрещён (наследие VLOOKUP, оставлено как валидация).
5. Удаление строки шаблона запрещено — только выключение; удалять можно только строки, добавленные вручную.
6. Балансные константы (см. §13) не хардкодятся по строкам, а задаются один раз.
