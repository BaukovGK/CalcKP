# Промт: прототип «Опросный лист + Конфигуратор/редактор расчёта»

Скопировать содержимое ниже в новую сессию (Claude design / генерация прототипа) целиком.

---

Ты — продуктовый дизайнер и фронтенд-инженер. Построй интерактивный прототип (один HTML-файл или React, всё в одном файле, без бэкенда, данные в памяти) двух связанных экранов веб-приложения «НТТ Калькулятор» — инструмента расчёта себестоимости стеклокомпозитных изделий завода. Русский интерфейс. Десктоп ≥1200px, но вёрстка должна выживать в 1000px (встройка iframe в Битрикс24). Две темы (тёмная по умолчанию, светлая) через CSS custom properties, переключатель в углу. Числа: разряды пробелами, tabular-nums.

## Экран 1 — Опросный лист (ОЛ) насосной станции

Визард из секций (вертикальный степпер слева, контент справа). Заполнение любой секции в любом порядке, черновик валиден. Секции и поля:

1. **Общие**: № заявки (текст), тип НС (Канализационная/Ливневая/Дренажная), заказчик, объект, стадия (проект/рабочая/кд/продажа/тендер), регион, дата.
2. **Корпус**: DN мм (300…3000, select), PN МПа (0,1…3,2), SN Па (1250/2500/5000/10000), возвышение над землёй мм, под проезжей частью (да/нет), по ТТ МВК (да/нет), теплоизоляция (да/нет → глубина мм).
3. **Патрубки**: два блока — подводящий и напорный: материал (ПЭ/ПВХ/ПНД/ПП/сталь/стеклокомпозит), DN мм, кол-во, глубина залегания лотка мм; тип запорной арматуры (select), кол-во задвижек, аварийный трубопровод (да/нет).
4. **Насосное оборудование**: максимальный приток (число + переключатель ЕИ: л/с | м³/ч | м³/сут), расчётный напор м, кол-во рабочих/резервных/запасных насосов, марка насоса (текст), взрывозащита (да/нет), дробилка/корзина (корзина|дробилка|обе|нет).
5. **Автоматика**: шкаф управления (да/нет → тип внутренний/уличный, пуск стандартный/плавный/ЧП), датчики давления/уровня (да/нет), расходомер (да/нет).

**Фирменная механика — live-расчёт справа от секции «Насосное» (панель «Подбор глубины»):**
```
Q = приток, л/с; n = рабочих насосов
Vэф  = Q·3.6/(4·10·n)            м³   (10 пусков в час)
Vмин = (Q·3.6/n)·5/60            м³
hраб = 4·Vмин/(π·(DN/1000)²)     м
hР   = hраб + 0.3 + 0.16 + 0.627 м
Нподз = ROUNDUP((глубина_лотка_подводящего/1000 + hР)·1000, до 100 вверх)  мм
```
Показывай значения живьём при вводе; итог «Рекомендуемая глубина подземной части: 11 600 мм» с двумя действиями: [Принять] / поле ручного ввода. Прогрессивное раскрытие: «нет» сворачивает зависимые поля. Кнопка «Создать расчёт →» внизу с превью: «КНС 3000×11900 мм (подз. 11 600), 25,13 л/с, 2+1 насоса, 7 блоков включено».

Предзаполни форму реальным кейсом: КНС, DN 3000, PN 0,1, SN 10000, приток 25,13 л/с, напор 12,9 м, насосы 2+1, марка VSL.100.55.4.5.0D, подводящий ПЭ DN250 ×1 (лоток 9910 мм), напорный ПЭ DN150 ×2, корзина, МВК: да, теплоизоляция 2000 мм, ШУ уличный, датчики: все.

## Экран 2 — Конфигуратор/редактор расчёта

Переход с экрана 1. Трёхзонная компоновка:

**Слева — дерево сборок** (сворачиваемое): 1 Корпус · 2 Лестница · 3 Перекрытие и площадка · 4 Вентиляционный стояк · 5 Напорный трубопровод · 6 Крепёж · 7 Оборудование и арматура. У каждой: тумблер включения, подытог ₽, бейдж проблем. Выключенная — полупрозрачная, подытог перечёркнут.

**Центр — таблица строк выбранной сборки.** Колонки: категория (чип) · наименование · кол-во · ЕИ · цена ₽ · сумма ₽ · ⋮. Строки группируются по компонентам (подзаголовки: «Обечайка корпуса», «Днище», «Патрубок входящий Ø400», «Теплоизоляция»…). Состояния ячеек — главный дизайн-контракт:

| Состояние | Вид |
|---|---|
| Расчётное значение | обычный текст, серый маркер «ƒ» при ховере с тултипом формулы |
| Override | синий текст + точка; ховер: «расчётное: 26,8 · [↺ вернуть]» |
| Нет цены | строка с красной подложкой, сумма «—», подсказка «указать цену» |
| Конфликт | янтарный значок ⚠ у значения; клик: «ОЛ изменился: было 11,6 → стало 12,1 · [Оставить моё] [Принять новое]» |
| ФОТ-спутник | вложенная строка с отступом и меткой «ФОТ», кол-во = масса×k, редактируемая |
| Выключено | вся строка-призрак |

Ввод количества принимает арифметику (`1.55*2+2.88*2` → хранится выражение, показывается 8,86). Шапка таблицы: счётчик «● 2 без цены · ⚠ 1 конфликт» — клик фильтрует. Кнопка «+ Добавить»: меню «Компонент из каталога…» (поиск с автодополнением) / «Свободная строка».

**Справа — закреплённая панель итогов** (обновляется анимированно при любой правке):
```
Материалы на закупку      9 268 103 ₽
Труба, муфта                 33 000 ₽
Формовка                    226 801 ₽
Работы, ФОТ                 918 838 ₽
Прочие затраты            1 189 686 ₽
─────────────────────────────────────
Себестоимость            11 603 440 ₽
Наценка               [ 0,43 ] ✎
ЦЕНА ПРОДАЖИ             16 593 000 ₽
Рентабельность                30,1 %
```
Кол-во корпусов [1] — при ≥2 вторая колонка «за N корп.».

**Топбар:** «Расчёт: КНС 3000×11900 · Заказчик АО «ГК «ЕКС»» · статус-бейдж DRAFT→CALC→REVIEW→APPROVED · кнопка «На проверку» (заблокирована при красных строках, тултип объясняет) · версия прайса «НН v2 от 20.05» · экспорт.

## Поведение (обязательно рабочее в прототипе)

1. Правка количества/цены → пересчёт суммы строки, подытога компонента, сборки и панели итогов.
2. Ввод цены в красную строку «Труба СК…» → строка становится обычной, кнопка «На проверку» разблокируется (если конфликт разрешён).
3. Тумблер сборки → строки-призраки, итог падает.
4. Override и возврат «↺» работают; конфликт разрешается обоими способами.
5. Изменение наценки → цена продажи `ROUNDUP(себестоимость×(1+наценка), до 100)` и рентабельность.
6. ФОТ-спутник пересчитывается при правке массы родителя (k=0,28 для «мех…», 0,56 для «ламин…»).

## Антицели

Не дашборд: никакой decorативной графики, это рабочий стол сметчика. Не прятать данные за кликами. Не упрощать терминологию (ОЛ, ФОТ, PN/SN, чел.ч). Не использовать браузерные alert/confirm.
