## 2. Ключевая находка: `ntt-calculator/doc/Шаблон 3.0.xlsx`

**Это тот самый мастер-шаблон** (2,3 МБ), описанный в `Реверс_калькуляторов.md` §2. Все 19 листов на месте. Соответствие имя→файл проверено через `xl/_rels/workbook.xml.rels`, а не по порядку:

| Лист | rId → файл | Размер | Содержимое |
|---|---|---|---|
| `НН` | rId18 → sheet18.xml | **709 КБ** | Прайс, ~1044 позиции |
| `Калькулятор КНС` | rId11 → sheet11.xml | **453 КБ** | Эталонная спецификация, 452 строки |
| `Вес трубы, ПЭ трубы` | rId17 → sheet17.xml | **151 КБ** | 162 строки GRP + 26 ПЭ |
| `Для расчетов` | rId16 → sheet16.xml | **105 КБ** | Инженерные матрицы |
| `Справка по подбору АШУ Омега` | rId19 → sheet19.xml | 62 КБ | ~220 шкафов |
| `Вспомогат. таблицы` | rId13 → sheet13.xml | 4,6 КБ | BOM монтажных петель |

**Следствия — план меняется в лучшую сторону:**

1. Справочники (веса труб, инженерные матрицы, АШУ, прайс) **извлекаются программно**, а не набиваются руками. Снимается главный риск этапа 3 и источник опечаток.
2. `sheet11.xml` содержит **формулы ячеек**, а не только значения. Шаблон КНС выводится **из первоисточника**, а не реконструируется из прозы. Это принципиально: проза §4.3 Реверса даёт ~10 формул из нескольких сотен.
3. Появляется **эталон формул**. ⚠️ **Важное ограничение (уточнено 2026-07-16):** `Шаблон 3.0.xlsx` — это *шаблон*, а **не** файл ОЛ3487. Его цена продажи — 8 229 200 ₽, часы фитингов — 649. Контрольные числа задачи (620,3 чел.ч → 16 593 000 ₽) взяты из файла ОЛ3487, **которого у нас нет**. Шаблон даёт: (а) точные формулы, (б) собственный самосогласованный кейс для тестов (наценка 0,43; рентабельность 30,07% — сходится). Построчной сверки с ОЛ3487 не будет — тесты §2 опираются на 5 чисел задачи, как и было задумано.

**Оговорка:** в книге есть `externalLinks` (7 шт.) — часть значений может быть ссылками на внешние файлы. Проверяется на этапе 1; если критичные данные окажутся внешними ссылками, потребуются исходные файлы.

### 4.2 Дефекты, найденные вне списка задачи

Обнаружены при инвентаризации; предлагаю чинить в рамках этапа 4.

1. **`PATCH /:id/survey` принудительно ставит `status:'CALC'` из любого статуса, включая APPROVED** (`estimates.routes.ts:139`), в обход таблицы переходов. Прямо ломает инвариант «APPROVED замораживает расчёт» (Механика §10). **Приоритет высокий.**
2. **Access- и refresh-токены структурно идентичны** (`utils/jwt.ts`): access-токен проходит `/api/auth/refresh`, refresh-токен принимается `requireAuth`. Нет `jti`, issuer, audience.
3. `requireAuth` доверяет claim роли в JWT и не перечитывает пользователя — отзыв роли или `isActive=false` не действует до истечения токена (15 мин).
4. `PriceHistory.changedById` — простая строка без FK на `User`.
5. `DELETE /api/projects/:id` не проверяет существование — несуществующий id даёт 500 вместо 404.
6. Два конкурирующих источника цен: статический `data/nomenclature.ts` (~17 позиций с `p: ''`) и `pricesApi`. Устраняется этапом 4 (`GET /api/refs/nomenclature` из БД).
7. `stores/auth.ts` в обход `api/client.ts` дублирует fetch/base-URL/localStorage.
8. `confirm()` внутри actions стора калькулятора — противоречит антицели хендоффа «не использовать браузерные alert/confirm» и делает стор нетестируемым.

### Этап 2. Движок расчёта — ✅ ВЫПОЛНЕНО (2026-07-16)

Приёмка закрыта: контрольные числа ОЛ3487 зелёные (ПЗР 56,4 · накладные 1 072 387 · цена 16 593 000 · рентабельность 30,07 %), инвариант §12.1 покрыт property-тестом, проверенным на способность падать (мутация «ПЗР в Прочие» валит 6 из 9). Тестов 123, `vue-tsc`/build/oxlint зелёные.

**Уточнения, найденные при разборе эталона:**
- **Корзины итогов определяются ЕИ, а не категорией** (`N441` суммирует по `K = "чел. ч"`, `K452` — по массе). Строка «Монтаж поплавковых выключателей» имеет категорию «Собственное производство», но ЕИ «чел. ч» — и идёт в труд. Классификация по категории дала бы неверные корзины. Труба/муфта по ЕИ неотличимы — помечаются явно.
- **Наивное округление завышает ФОТ.** `Math.ceil(x*10)/10` на массах 2,5 / 5 / 10 кг с k = 0,28 даёт +0,1 чел.ч из-за двоичной погрешности. Лечится снапом до 15 значащих цифр (так делает Excel). Шесть случаев закреплены регрессией.
- **Баг мёртвого кода:** `cost.ts::fotCoeff` возвращал 0,28 на любое вхождение «формов» — то есть и для «Ручной формовки» (положено 1,0). Не вызывался ниоткуда; удалён.

Состав (исходный план этапа, выполнен):
- `engines/`: чистые функции, никакого Vue/Pinia — тестируемость.
  - `row.ts` — двухканальный override; безопасный парсер арифметики (`1.55*2+2.88*2`) **без eval**; строка «без цены» → сумма 0.
  - `fot.ts` — спутники: `ROUNDUP(масса×k; 0,1)`, k = 0,28 (`*мех*`) / 0,56 (`*ламин*`) / 1,0.
  - `economics.ts` — §9.5: часы фитингов/РМУ (по `*изготов*`), масса формовки (ЕИ=кг), ПЗР, ацетон, СИЗ, накладные, 5 корзин, цена = `ROUNDUP(себест×(1+наценка); до 100)`, рентабельность.
  - `rounding.ts` — `roundUp(value, step)` единой реализацией (ROUNDUP до 0,1 / до 100 — один источник истины).
- **Тесты (Vitest):** контрольные числа ОЛ3487 из задачи §2. ⚠️ Построчной сверки с эталоном **не будет** — `Шаблон 3.0.xlsx` содержит другой кейс (цена 8 229 200, часы 649), а файла ОЛ3487 у нас нет. Вместо этого сверен собственный кейс шаблона: `J441`=649, `J443`=59, `J445`=44,7, `J446`=951, `J447`=708 — все сходятся.
- **Приёмка:** ПЗР 56,4; накладные 1 072 387; цена 16 593 000; рентабельность 30,07%. Инвариант Механики §12.1 (итог = сумма включённых строк + начисления) — property-тестом.
