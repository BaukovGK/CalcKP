# НТТ Калькулятор

Расчёт стоимости изделий из стеклокомпозита (КНС, ЕМК, колодцы). Заменяет
Excel-книгу на 19 листов.

**Процесс:** опросный лист → материализация спецификации → тюнинг строк → КП →
согласование в коммерческом отделе (вне системы) → проработка инженером →
сметы и заявка на закупку.

```
backend/          Express 5 + Prisma 7 + PostgreSQL 16   :3000
ntt-calculator/   Vue 3 + Pinia + Vite                   :5173
doc/              ТЗ, механика, библиотека компонентов, план реализации
design_handoff_.../  прототипы и токены дизайна
```

Печатная форма КП (`GET /api/estimates/:id/kp/export?format=docx` или `pdf`,
опционально `&version=N`) строится на бэкенде из снапшота выпущенного КП:
пакеты `docx` и `pdfmake` 0.2 со встроенным Roboto. Ни LibreOffice, ни шрифтов
в системе сервера не требуется. Если снапшотов нет — `422 KP_NOT_ISSUED`,
сначала `POST /api/estimates/:id/kp` (гейт по строкам без цены + снапшот).

## Запуск

### Требования

- **Node 20+** (проверено на 24.18)
- **PostgreSQL 16** на `localhost:5432`

### 1. Роль и база

Их нужно создать один раз. Пароль возьмите из `DATABASE_URL` в `backend/.env`:

```powershell
& "C:\Program Files\PostgreSQL\16\bin\psql.exe" -U postgres -c "CREATE ROLE ntt WITH LOGIN PASSWORD '<пароль>'"
& "C:\Program Files\PostgreSQL\16\bin\psql.exe" -U postgres -c "CREATE DATABASE ntt_estimates OWNER ntt"
& "C:\Program Files\PostgreSQL\16\bin\psql.exe" -U postgres -c "ALTER ROLE ntt CREATEDB"
```

`CREATEDB` нужен только в разработке: `prisma migrate dev` создаёт shadow-базу.

### 2. Конфигурация

```powershell
Copy-Item backend\.env.example backend\.env
Copy-Item ntt-calculator\.env.example ntt-calculator\.env
```

В `backend/.env` задайте `DATABASE_URL` и `JWT_SECRET`:

```powershell
node -e "console.log(require('crypto').randomBytes(48).toString('base64url'))"
```

### 3. Сборка и проверка

```powershell
.\verify.ps1
```

Скрипт делает всё с нуля и **проверяет результат**: зависимости → миграции →
сид справочников → сборка обоих приложений → тесты движка → smoke-проверка
живого API (логин, прайс, ставка ФОТ, веса труб, контрольное число).

Флаги: `-SkipInstall` · `-SkipSeed` · `-KeepRunning`.

### 4. Разработка

```powershell
cd backend;        npm run dev    # :3000
cd ntt-calculator; npm run dev    # :5173
```

**Учётные записи.** Сид заводит одного пользователя — первого администратора
`admin@ntt.local`, без которого в свежую систему было бы не войти. Пароль —
из `ADMIN_INITIAL_PASSWORD` (не короче 8 знаков), без неё — случайный: сид
печатает его в лог один раз, при создании учётной записи. При первом входе
пароль обязательно сменить — до смены экран ведёт на неё, а сервер отвечает
403 `PASSWORD_CHANGE_REQUIRED` на всё, кроме смены пароля. Остальные
пользователи заводятся в разделе «Администрирование» и тоже меняют пароль
при первом входе; забытый пароль администратор сбрасывает там же —
система выдаёт временный.

Демо-учётки остальных ролей создаются **только** при `SEED_DEMO_USERS=1` —
это режим локальной разработки (`verify.ps1` выставляет флаг сам, ему нужен
логин инженером для smoke-проверки):

| Логин | Пароль | Роль |
|---|---|---|
| `manager@ntt.local` | `manager123` | MANAGER |
| `engineer@ntt.local` | `engineer123` | ENGINEER |
| `technolog@ntt.local` | `technolog123` | TECHNOLOG — шаблоны (`/templates`) |
| `viewer@ntt.local` | `viewer123` | VIEWER — только просмотр (вкладка Битрикс24) |

Список — `DEMO_USERS` в `backend/prisma/seed.ts`. Шестая роль схемы, `BUYER` (импорт
прайса), учётки в сиде не имеет — проверяйте `/prices` под `admin@ntt.local`.

## Docker

Проверено на Docker 29.6.1 / Compose v5.3.0. Поднимает стек с нуля: PostgreSQL
→ миграции → сид справочников → backend → nginx с собранным фронтом.

```bash
cp .env.example .env      # заполните POSTGRES_PASSWORD и JWT_SECRET
docker compose up --build
```

Приложение — на `http://localhost:${HTTP_PORT:-80}`. Сид выполняется при
каждом старте и только досоздаёт недостающее, так что чистый том сразу даёт
рабочую систему. Справочники материализации он заливает только в пустую базу:
дальше их ведёт технолог, и перезапуск его правок не трогает.

Полезное:

```bash
docker compose logs -f backend    # миграции и сид видно здесь
docker compose down               # остановить
docker compose down -v            # + удалить том с базой (данные пропадут!)
```

Бэкап и восстановление:

```bash
docker compose --profile tools run --rm backup                # снять дамп
docker compose --profile tools run --rm restore --list        # что есть
docker compose --profile tools run --rm restore --yes latest  # восстановить
```

Дампы — в `./backups` на хосте. Перед применением миграций контейнер снимает
дамп сам и **не стартует, если это не удалось**: у `prisma migrate deploy` нет
обратного хода, и восстановление из дампа — единственный путь назад. Подробно,
включая порядок отката неудачной миграции и регулярный бэкап по cron, —
в `РАЗВЁРТЫВАНИЕ.md`, раздел «Бэкап базы и откат миграции».

## Развёртывание через GitHub

Репозиторий: `https://github.com/BaukovGK/CalcKP.git`. CI/CD — в
`.github/workflows/ci-cd.yml`. Пошаговый runbook — `РАЗВЁРТЫВАНИЕ.md`.

**Релиз:** `git push` в `master` (доступ по HTTPS + токен). Каждый push
запускает CI, а при зелёных тестах — авто-деплой на сервер.

**CI** (на каждый push и pull request): typecheck фронта, линт (`npm run
check:lint` — проверяющий вариант без `--fix`) и тесты фронта; на бэке —
`prisma migrate deploy` и сид против сервисного Postgres, затем сборка
(`npm run build`) и тесты бэка (числа — в «Тестах» ниже). Ловит расхождение
схемы и миграций до деплоя. Третья задача — документы: ссылки на код в них
только по имени, без номеров строк (`node tools/check-doc-refs.mjs`).
Линта у бэкенда нет.

**Деплой** (автоматически при push в `master` после зелёного CI): GitHub
заходит на сервер по SSH и выполняет `git reset --hard origin/master` +
`docker compose up -d --build --wait` — и ждёт, пока бэкенд станет healthy.
Не поднялся за 3 минуты — деплой красный, в логе job — хвост логов бэкенда.
Настройка — один раз (подробно в
`РАЗВЁРТЫВАНИЕ.md`):

1. Сервер: Docker, `git clone` по HTTPS с токеном на чтение, `cp .env.example .env`
   (заполнить `POSTGRES_PASSWORD`, `JWT_SECRET`, `PUBLIC_URL`), `docker compose up`.
2. **Settings → Secrets and variables → Actions** — секреты доступа к серверу:

   | Секрет | Назначение |
   |---|---|
   | `DEPLOY_SSH_HOST` | адрес сервера |
   | `DEPLOY_SSH_USER` | пользователь SSH |
   | `DEPLOY_SSH_KEY` | приватный ключ (публичный — в `authorized_keys` сервера) |
   | `DEPLOY_SSH_PORT` | порт SSH (необязательно, по умолчанию 22) |
   | `DEPLOY_PATH` | путь к каталогу репозитория на сервере |

`.env` в git не хранится (только `.env.example`) — он живёт на сервере и
переживает деплой. Для вкладки в Битрикс24 (ТЗ §10.1) `PUBLIC_URL` — домен с
валидным TLS.

## Справочники

Прайс, веса труб и списки извлекаются из мастер-шаблона
`ntt-calculator/doc/Шаблон 3.0.xlsx` — это исходная Excel-книга завода.

```powershell
cd backend; npm run refs:extract     # → prisma/seed-data/*.json
npm run db:seed                      # → в базу
```

Экстрактор падает при расхождении контрольных чисел — лучше упасть, чем
засеять мусор: 162 GRP-трубы, 26 ПЭ, 16 категорий, ставка ФОТ по тройному
ключу «ФОТ / ФОТ / чел. ч», вес DN3000 = 970,2 кг/пм, инженерные матрицы
(блок «Проверки целостности» в `main`, `backend/tools/extract-refs.ts`). Прайс проверяется мягко — порогом
`prices.length < 900` (`extract-refs.ts`): точного контрольного числа у
него нет, сейчас извлекается 1043 позиции.

Каталог насосов из шаблона **не извлекается**: `prisma/seed-data/pumps.json`
(61 модель Vandjord VSL) лежит в репозитории готовым и грузится сидом в
таблицу `Pump` (`seedPumps` в `backend/prisma/seed.ts`).

Прайс версионируется целиком: импорт через UI (`/prices`, роли ADMIN и BUYER)
и правка цены на том же экране создают новую версию и пишут `PriceHistory`.
Активную версию (максимальную) фронт запрашивает у `GET /api/refs/price-version`.
Расчёт хранит версию, по которой посчитаны его цены, и ставки экономики того
же прайса; разошлись с действующим — экран предлагает пересчитать.

## Тесты

```powershell
cd ntt-calculator; npm test     # 910 тестов в 51 файле
cd backend;        npm test     # 332 теста в 23 файлах
node tools/check-doc-refs.mjs   # из корня: ссылки на код в документах — без номеров строк
```

**Упал тест «сборка совпадает с последней редакцией»** (`engines/builtin-revisions.test.ts`)
— правка меняет то, что программа строит из опросного листа: состав или
формулы встроенных узлов, встроенный шаблон, исполнение узлов каталога. Если
так и задумано, заведите новую редакцию в
`ntt-calculator/src/engines/builtin-revisions.ts`: номер, дату, что изменилось
словами инженера и отпечаток из текста ошибки. Редакция уходит в дерево и
снапшот КП, а расчёты, собранные прежней, предложат пересборку.

Порядок прогона относительно `npm run build` значения не имеет: тесты
исключены из сборки (`exclude` в `backend/tsconfig.json`), а
`backend/vitest.config.ts` сужает `include` до `src/**`. `verify.ps1` гоняет
только фронтовый набор.

Ядро фронтового набора — контрольные числа реального расчёта ОЛ3487 (задача §2):

| Проверка | Значение |
|---|---|
| ПЗР при часах фитингов 620,3 | 56,4 чел.ч |
| Накладные (620,3 + 56,4) × 1584,73 | 1 072 387 ₽ |
| Цена от себестоимости 11 603 440 | 16 593 000 ₽ |
| Рентабельность | 30,07 % |
| Нподз (DN3000, 25,13 л/с, 2+1) | 11 600 мм |

Инвариант §12.1 («итог = сумма включённых строк + начисления») покрыт
property-тестом, проверенным на способность падать.

Бэковый набор — чистые модули без БД: модель печатной формы КП
(`src/utils/kp-document.ts`), диаметр напорного трубопровода
(`pipe-hydraulics.ts`), подбор насоса (`pump-selection.ts`), габарит КНС
(`pump-station-dimensions.ts`), кольцевая жёсткость (`ring-stiffness.ts`),
проверка узлов каталога и шаблонов изделий (`catalog.ts`).
