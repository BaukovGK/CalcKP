# Handoff: НТТ Калькулятор — Опросный лист + Конфигуратор расчёта

## Обзор

B2B-инструмент расчёта себестоимости и цены промышленных изделий из стеклокомпозита (насосные станции, ёмкости, колодцы) для завода ООО «НТТ». Заменяет Excel-книгу на 19 листов. Ключевое ощущение: **«управляю изделием, а не таблицей»**.

Флоу: инженер заполняет Опросный лист (ОЛ) → система материализует спецификацию из сотен строк с формульными количествами и ценами из прайса → инженер точечно «тюнингует» строки → менеджер проверяет и утверждает → итог уходит в Битрикс24.

Проработано в этой дизайн-сессии: два связанных интерактивных прототипа (Опросный лист и Конфигуратор/Калькулятор) + вайрфреймы всех вариантов компоновок.

## О файлах в архиве

Файлы в этом пакете — **дизайн-референсы, созданные в HTML** (Design Components: HTML-шаблон + JS-класс логики). Это прототипы, показывающие целевой вид и поведение, а НЕ production-код для прямого копирования. Задача разработчика — **воссоздать эти интерфейсы в целевом стеке проекта** (React/Vue/…, по требованиям ТЗ), используя его паттерны и библиотеки. Если стек не выбран — выбрать наиболее подходящий (SPA-фреймворк с быстрым виртуализированным рендером таблиц 300–450 строк).

Файлы `*.dc.html` открываются в браузере напрямую (нужен рядом `support.js`). Внутри каждого: секция `<x-dc>` — разметка с inline-стилями, `<script data-dc-script>` — класс `Component` со всей логикой, формулами и мок-данными.

## Fidelity

- `Калькулятор v2.dc.html`, `Опросный лист v2.dc.html` — **hi-fi интерактивные прототипы**: финальные токены цветов (обе темы), типографика, все состояния ячеек, рабочая логика пересчёта. Воссоздавать близко к пикселю.
- `Вайрфреймы.dc.html` — **lo-fi**: история исследования компоновок (варианты 1a/1b/1c, 2a/2b, 3a/3b/3c, 4a). Полезно для понимания принятых решений; в реализацию не идёт.
- `Калькулятор.dc.html`, `Опросный лист.dc.html` — ранние итерации (v1), сохранены для контекста; актуальны v2.

## Жёсткие ограничения контекста запуска

1. **Standalone SPA** — полноэкранный режим.
2. **Iframe внутри Битрикс24 (облако)**: нельзя рассчитывать на всю высоту вьюпорта (resize через BX24 API), нет своих top-level навбаров, нет third-party cookies, вёрстка живёт в ~900–1200px ширины. Одна вёрстка на оба контекста; в прототипах min-width 1000px, таблица получает горизонтальный скролл на узких окнах.
3. **Темизация**: тёмная (по умолчанию) и светлая темы через CSS custom properties (`data-theme` на `<html>`). Все цвета — только токенами. Обе темы — WCAG AA.
4. Язык — русский; профессиональную терминологию не упрощать (ОЛ, ФОТ, PN/SN, чел.ч).

## Экраны

### 1. Опросный лист (`Опросный лист v2.dc.html`)

**Назначение**: анкета изделия; заполняется в любом порядке, черновик валиден.

**Компоновка**: 3 колонки — степпер секций (190px, слева) · форма (центр, max-width 820px) · закреплённая live-панель «Подбор глубины» (300px, справа). Топбар: название, № заявки, время сохранения черновика, ссылка на конфигуратор, переключатель темы.

**Секции и поля** (предзаполнены реальным кейсом):
1. **Общие**: № заявки (2406-118), тип НС (Канализационная/Ливневая/Дренажная), стадия (проект/рабочая/КД/продажа/тендер), заказчик (АО «ГК «ЕКС»), объект (ГКБ №52, ул. Пехотная, 3), регион, дата.
2. **Корпус**: DN select (300…3000 → 3000), возвышение над землёй (300 мм), блок «Труба корпуса»:
   - **PN/SN не задаются пользователем** — они продиктованы глубиной и требованиями заказчика. Расчёт: SN по глубине (>8000 мм → 10000; >5000 → 5000; >3000 → 2500; иначе 1250), «под проезжей частью» или «ТТ МВК» поднимают SN на ступень (потолок 10000). PN по умолчанию 0,1 (безнапорный корпус).
   - Показ: марка «СК/НПС-К 3000-0,1-10000» + пояснение расчёта. Чекбокс «изменить вручную» раскрывает панель с селектами PN/SN (панель с синей левой рамкой на синей подложке); «↺ вернуть расчётные» снимает ручной режим.
   - Тумблеры да/нет: под проезжей частью (нет), по ТТ МВК (да), теплоизоляция (да → раскрывается «Глубина теплоизоляции, мм» = 2000).
3. **Патрубки**: две карточки — Подводящий (ПЭ, DN250, ×1, глубина лотка 9910 мм — обязательное) и Напорный (ПЭ, DN150, ×2, лоток 1800). Материалы: ПЭ/ПВХ/ПНД/ПП/сталь/стеклокомпозит. Ниже:
   - **Задвижки — подводящие (безнапорные)**: ƒ = кол-ву подводящих патрубков (=1). Задвижки ставятся только на безнапорные подводящие трубопроводы.
   - **Шаровые краны — напорная линия**: ƒ = напорные линии (раб+рез) + коллектор 1 (+1 при аварийном трубопроводе) = 4.
   - Оба поля: подсказка-разбивка формулы под полем, ручной override (значение синеет) + ↺ возврат.
   - Аварийный трубопровод (да/нет).
4. **Насосное оборудование**: максимальный приток (25,13 + переключатель ЕИ л/с | м³/ч | м³/сут с конвертацией значения), расчётный напор (12,9 м), рабочих/резервных/запасных (2/1/0), марка (VSL.100.55.4.5.0D), взрывозащита (нет), дробилка/корзина (select: корзина/дробилка/обе/нет).
5. **Автоматика**: ШУ (да → раскрываются тип внутренний/уличный и пуск стандартный/плавный/ЧП), датчики давления (да), датчики уровня (да), расходомер (да).

**Фирменная механика — live-панель «Подбор глубины»** (акцентная, всегда видна, пересчёт при каждом вводе):
```
Q     = приток, приведённый к л/с
Vэф   = Q·3,6 / (4·10·n)          м³   (10 пусков в час, n = рабочих насосов)
Vмин  = (Q·3,6/n)·5/60            м³
hраб  = 4·Vмин / (π·(DN/1000)²)   м
hР    = hраб + 0,3 + 0,16 + 0,627 м
Нподз = ROUNDUP((лоток_подводящего/1000 + hР)·1000, до 100 вверх)  мм
```
Контрольные значения при предзаполнении: Q 25,13 → Vэф 1,13 · Vмин 3,77 · hраб 0,533 · hР 1,620 → **Нподз = 11 600 мм**. У каждой величины title-тултип с формулой (маркер ƒ). Действия: [Принять] (переносит в поле ручного ввода, кнопка меняется на «Принято ✓») / поле «своя, мм». Ниже — мини-превью изделия: «КНС 3000×11900 мм · подз. 11 600 мм · 25,13 л/с · 2+1 насоса · 7 блоков включено».

**Прогрессивное раскрытие**: «нет» сворачивает зависимые поля (теплоизоляция → глубина; ШУ → тип/пуск).

**Финал**: кнопка «Создать расчёт →» (заблокирована при пустых обязательных, hint объясняет) → модал-превью: заголовок «КНС 3000×11900 мм», подзаголовок с параметрами, список блоков ☑/☐ → «Создать расчёт → конфигуратор» (переход на экран 2).

### 2. Конфигуратор расчёта (`Калькулятор v2.dc.html`)

**Назначение**: главный экран, 80% времени. Таблица ~30+ строк (в реальности 300–450) со всей сметой.

**Компоновка** (три зоны): дерево сборок (224px) · таблица (центр, вся смета одной лентой с группировкой) · панель итогов (264px, закреплена). Сверху: топбар + панель фильтров.

**Топбар**: «Расчёт: КНС 3000×11900 · Заказчик АО «ГК «ЕКС»», ссылка «← Опросный лист», статус-бейдж, кнопка-счётчик проблем «● 1 без цены · ⚠ 1 конфликт» (клик включает фильтр проблем), версия прайса «НН v2 от 20.05», Экспорт, тема, кнопка перехода статуса.

**Статусная модель**: DRAFT → CALC → REVIEW → APPROVED; REVIEW → CALC (возврат). «На проверку» **заблокирована** при красных строках или неразрешённых конфликтах — tooltip и тост объясняют причину. APPROVED: зелёный баннер «расчёт утверждён — снапшот создан», вся таблица read-only, «Новая версия» возвращает в CALC.

**Дерево сборок** (7 шт): 1 Корпус · 2 Лестница · 3 Перекрытие и площадка · 4 Вентиляционный стояк · 5 Напорный трубопровод · 6 Крепёж · 7 Оборудование и арматура. У каждой: чекбокс-тумблер включения, подытог (млн/тыс), бейджи проблем (красный ●N / янтарный ⚠N). Клик по имени — плавный скролл таблицы к группе; при прокрутке активная группа подсвечивается (scrollspy, левая акцентная рамка). Выключенная сборка: полупрозрачная, подытог перечёркнут, строки-«призраки» (opacity .38), из итога исключена.

**Панель фильтров**: поиск по наименованию (200px) · чипы состояний «● без цены · N» / «⚠ конфликты · N» / «override · N» (живые счётчики, toggle) · «сбросить ✕» · чекбокс «выключенные» · «показано N из M».

**Таблица**. Колонки: `104px (категория-чип) · minmax(180px,1fr) (наименование) · 96px (кол-во) · 52px (ЕИ) · 96px (цена ₽) · 100px (сумма ₽) · 168px (примечание/действия)`; gap 8px, строка 32px, зебра через одну, min-width 820px с горизонтальным скроллом. Шапка колонок sticky top:0; заголовки групп sticky top:25px. Внутри групп — подзаголовки компонентов («└ Обечайка корпуса», «└ Днище»…) с подытогами. Длинные ГОСТ-имена: ellipsis + полный текст в title.

**Состояния ячеек — главный дизайн-контракт**:

| Состояние | Вид | Поведение |
|---|---|---|
| Расчётное | обычный текст; тултип «ƒ расчёт из ОЛ: …» | значение из формулы |
| Override | **синий** текст + синяя точка в углу ячейки + синяя рамка; слева от ячейки кнопка ↺ | тултип показывает расчётное и сохранённое выражение; ↺ возвращает расчётное |
| Нет цены | строка на красной подложке, ячейка цены красная с placeholder «цена?», сумма «—», примечание «указать цену» | ввод цены снимает состояние и разблокирует «На проверку» |
| Конфликт | янтарная рамка+подложка ячейки, ⚠ в бейджах; в примечании «было 17,2 · [Оставить моё] [Принять новое]» | «Оставить моё» гасит конфликт, «Принять новое» сбрасывает override к расчётному |
| ФОТ-спутник | вложенная строка с отступом 30px, пунктирная рамка ячеек, приглушённый текст, метка «ФОТ · k=0,28» | кол-во = масса родителя × k, живой пересчёт при правке родителя; редактируемо (override) |
| Выключено | вся строка-призрак opacity .38, ввод disabled | не входит в итог |

**Ввод**: арифметика в ячейках (`1,55*2+2,88*2` — хранится выражение, показывается результат); live-группировка разрядов при вводе чисел (980000 → 980 000); Enter — применить и вниз; ↑↓ по строкам; ←→ кол-во⇄цена; Esc — отмена. Фокус — синее свечение, значение выделяется для перепечатки.

**Данные сборки «Корпус»** (использованы дословно): Труба СК/НПС-К 3000-0,1-10000 — 11,6 м — **нет цены**; Придание изделию товарного вида — 26,8 чел.ч × 1207,8; Механическое формованное дно — 262,8 кг × 214,4 + ФОТ-спутник k=0,28 (73,6 чел.ч); Ламинирование дна к фальшполу — 78,9 кг × 310,2 + ФОТ-спутник k=0,56 (44,2 чел.ч); Стеклокомпозитная гильза Ø400 — **override 0,5** шт (расчётное 1) × 12 400; Болт М16-6gх80.58.12Х18Н10Т ГОСТ 7798-70 — 32 шт × 96; Изофом ППЭ ОР 15 1,5х40 — **конфликт** (override 18,85, расчётное 17,2) × 890. «Оборудование и арматура»: Насос VSL.100.55.4.5.0D ×3, Задвижка чугунная клиновая DN150 5×25 000, Поплавковый выключатель 4×6 000, Шкаф АШУ40-011-54-21У 1×480 000, ПНР, доставка.

**Добавление строк**: «+ Компонент из каталога…» — модал с поиском по прайсу (категория · наименование · ЕИ · цена; клик добавляет в активную сборку); «+ Свободная строка» — рождается красной (без цены). Пользовательские строки удаляются по ✕.

**Панель итогов** (живой пересчёт, изменившиеся суммы вспыхивают акцентом ~0,8s):
```
Материалы на закупку · Труба, муфта · Формовка · Работы, ФОТ · Прочие затраты
─ Себестоимость (жирная, над ней 2px рамка)
─ Наценка [0,43] ✎ (редактируемая)
─ ЦЕНА ПРОДАЖИ = ROUNDUP(себестоимость × (1+наценка), до 100)  — 15px, жирная
─ Рентабельность % (зелёная ≥25, янтарная ≥15, красная <15)
```
Поле «корпусов [N]» — при N≥2 появляется строка «за N корп.». Внизу — легенда клавиш и подсказка про override.

Категоризация в корзины итогов: труба и муфта → «Труба, муфта»; cat ФОТ → «Работы, ФОТ»; «Собственное производство» → «Формовка»; «Прочие затраты» → «Прочие затраты»; остальное → «Материалы на закупку».

## Interactions & Behavior (обязательно рабочее)

- Правка кол-ва/цены → пересчёт суммы строки, подытога компонента, сборки, панели итогов — мгновенно, с анимацией итога.
- Ввод цены в красную «Трубу СК…» → строка обычная, «На проверку» разблокируется (если конфликт тоже разрешён).
- Тумблер сборки → призраки, итог падает.
- Override/↺ и разрешение конфликта обоими способами.
- ФОТ-спутник пересчитывается при правке массы родителя.
- Тосты (не браузерные alert/confirm) для всех подтверждений.
- Модал закрывается по фону; контент останавливает всплытие.
